## Product and protocol decisions

- Keep Code Mode as a separate repo and product from `houdini-cli`.
- Keep one MCP tool rather than mirroring HOM as hundreds of tools.
- Use raw `hou` for API completeness and `ctx` only for bounded projections,
  compound workflows, and audited effects.
- Keep model recursion, provider choice, sessions, and notebook memory above
  the Houdini boundary. The scene is the durable state; user globals are fresh
  per run.
- Keep the human/debug CLI (`check`, `run`, `doctor`) even though the model sees
  one tool.
- Treat execution as trusted local code, not a sandbox.
- Marshal whole programs to `MainThread`. Arbitrary Python is not safely
  preemptible; a wait timeout means completion is unknown, not cancellation.
- Never save the HIP implicitly. Undo grouping organizes history but is not a
  transaction or rollback mechanism.

## Implemented runtime

The runtime/controller now provides:

- versioned request, response, error, policy, runtime, and protocol contracts;
- source/result/response/log/string/container/depth/total-item byte and item
  limits;
- Unicode-aware bounded stdout/stderr and exactly one `result.emit()`;
- structured compile/execution/result/busy/connection errors;
- netref-free normalization with compact node/parm/type summaries;
- a Houdini-side non-blocking run lock plus the legacy-compatible Windows
  endpoint mutex namespace;
- a background waiter that keeps the local endpoint gate after caller timeout;
- cached runtime installation by version/source hash;
- exact helper-owned mutation events and honest best-effort direct-HOM tracking;
- a Code Mode-owned loopback shelf bootstrap.

Current `ctx` services are discoverable at runtime with:

```python
result.emit(ctx.capabilities())
```

Targeted exact signatures/effect categories are returned by:

```python
result.emit(ctx.help("ctx.hda.plan_update"))
```

One static host registry generates the embedded discovery data. Tests compare
the registry with every public service and method to catch drift.

## Implemented semantic extensions

- `ctx.nodes`: bounded summaries, descendants, filtering, neighbors, and
  network summaries.
- `ctx.parms`: bounded listing/filtering and caller-ordered projection.
- `ctx.geometry`: topology summaries, attribute definitions, and bounded
  samples.
- `ctx.cop`: Copernicus output metadata and pixel sampling.
- `ctx.cop_files`: transactional, byte-capped raw/view export and bounded File
  COP import. Export renders to a temporary sibling, validates it, and only then
  atomically replaces the final path; failures preserve existing files.
- `ctx.lop`: bounded USD-stage traversal, counts, type histograms, paths,
  composition, and render-context metadata.
- `ctx.opencl`: validate/sync across SOP, COP, and DOP with connection/value
  preservation behavior.
- `ctx.python`: Python SOP/COP `#bind` inspect/validate/sync.
- `ctx.wrangle`: spare-parameter sync/clear.
- `ctx.artifacts`: manifest-only `.asData` export/inspect/import/list/remove.
  Narrow value/parm/input inverses are used only when the captured root scope
  contains nothing broader; normal full node artifacts correctly use
  `setFromData` because they also capture flags, position, inputs, and other
  state.
- `ctx.hda`: bounded instance/definition/library inspection, H22-compatible
  external-reference auditing, strict/optional reference validation,
  fresh-instance/frame-cook/interface validation, no-effect parameter promotion
  planning, and no-effect package/update/copy planning.

## Skill and MCP guidance design

The MCP metadata intentionally contains only the universal operating contract:
one complete program, fresh globals, JSON args, one compact emission, raw `hou`,
runtime discovery, trusted execution, no implicit save, and unknown-completion
recovery. It does not contain the entire API catalogue.

The bundled `skills/houdini-codemode` skill owns behavior and judgment:

- prefer Code Mode over GUI clicks, legacy `houdini-cli eval`, or repeated tiny
  calls;
- compose discovery, edits, validation, and evidence into one program;
- choose native nodes vs VEX/OpenCL/Python appropriately;
- enforce Copernicus coordinate/binding rules and solver/HDA cautions;
- use prepared, version-matched Houdini/VEX help rather than guessing;
- clean temporary scene/file effects and handle timeout recovery honestly.

Durable CLI skill knowledge was migrated into progressive-disclosure references
for Copernicus, native Cop kernels, OpenCL SOPs, Gas OpenCL/DOPs, and recipes.
Legacy command examples were rewritten as complete Code Mode programs.

The help-extraction script is included at
`skills/houdini-codemode/scripts/prepare_houdini_help.py`. Only the generated
`references/help_prepared/` corpus is excluded and ignored. The default command
is:

```powershell
python <installed-skill>\scripts\prepare_houdini_help.py `
  --source "<houdini-install>\houdini\help"
```

## Recommended next implementation slice

Do not jump directly to broad HDA mutation. First choose one narrowly scoped
operation and lock its acceptance contract. The safer candidate is package/copy
to a new explicitly owned destination library because it can avoid overwriting
the source definition. Require `overwrite=False` by default, a preflight plan,
external-reference review, an optional backup when replacing, before/after file
hashes, bounded result metadata, no implicit install/save, and a live test using
a temporary library outside the Houdini installation.

Parameter promotion should remain plan-only until the package/update write and
backup conventions are proven, because promotion combines interface mutation,
channel rewrites, definition update, and library write in one operation.
